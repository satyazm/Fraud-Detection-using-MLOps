## Overview

Built on the [PaySim](https://www.kaggle.com/datasets/ealaxi/paysim1) synthetic mobile-money dataset (**6,362,620 transactions, 0.13% fraud**), this project is a hands-on reference for how the pieces of a production ML system fit together — not just a model, but everything around it:

- **Train & track** four models with MLflow, handle the extreme class imbalance, and register the best one.
- **Stream** transactions through Kafka and compute features with a real PyFlink job into a Feast/Redis online store.
- **Serve** fraud probabilities from a FastAPI service that reads precomputed online features and the MLflow *Production* model.
- **Observe** it with Prometheus, Grafana and Evidently AI drift reports.
- **Operate** it with Docker, Kubernetes (HPA + Ingress), Airflow DAGs and GitHub Actions CI.

One design rule runs through the whole codebase: **there is exactly one implementation of every feature**, shared by offline training, the streaming job and the API, so training/serving skew cannot creep in ([ADR-0003](docs/decisions/0003-shared-feature-pipeline.md)).

## Architecture

![Fraud detection platform architecture](docs/images/architecture-overview.png)

Two paths meet in Redis — an **asynchronous feature path** and a **synchronous prediction path**:

```mermaid
flowchart LR
    subgraph OFF["Offline (batch)"]
        D[(PaySim CSV)] --> P[ingest · validate · preprocess<br/>temporal split]
        P --> T[train 4 models]
        T --> M[(MLflow<br/>tracking + registry)]
    end

    subgraph ASYNC["Asynchronous feature path"]
        PR[Kafka producer] --> K[[Kafka<br/>transactions]]
        K --> F[PyFlink worker<br/>FeaturePipeline.transform_one]
        F -->|write_to_online_store| R[(Redis<br/>Feast online store)]
    end

    subgraph SYNC["Synchronous prediction path"]
        C[client] -->|POST /predict| A[FastAPI]
        A -->|get_online_features| R
        M -.->|Production model,<br/>loaded once| A
        A --> O[fraud probability]
    end

    subgraph OBS["Observability & operations"]
        A -->|/metrics| PM[Prometheus] --> G[Grafana]
        A -->|prediction log| E[Evidently drift report]
        AF[Airflow DAGs] -.->|materialize · retrain · drift| OFF
        KS[Kubernetes + HPA] -.->|runs| SYNC
    end
```

> If a transaction's features are not in Redis yet, `/predict` returns **503** rather than silently recomputing them — features are computed once, in the stream.

## Results

Model comparison on the full dataset with a **chronological split** (train on the earliest `step`s, validate on the next, test on the latest — see the [training guide](docs/guides/training-and-mlflow.md)). Generated by `make train` → [docs/model_report.md](docs/model_report.md).

| Model | PR-AUC (val) | ROC-AUC (val) | Precision (val) | Recall (val) |
|---|---|---|---|---|
| Logistic Regression | 0.9184 | 0.9999 | 0.0874 | 1.0000 |
| Random Forest | 1.0000 | 1.0000 | 1.0000 | 1.0000 |
| XGBoost | 1.0000 | 1.0000 | 1.0000 | 1.0000 |
| LightGBM | 0.9940 | 1.0000 | 0.9912 | 1.0000 |

The registered model (Random Forest — it ties XGBoost on validation) scores test PR-AUC 1.0000 with TP=3998, FP=0, FN=8, TN=914,611.

**Read these numbers with care.** PR-AUC, not accuracy, is the selection metric (a model that never predicts fraud is 99.87% "accurate"). But PaySim is synthetic and its fraud has an easy tell — in the XGBoost model, two balance-consistency features carry ~92% of the importance — so near-perfect scores do **not** imply real-world performance. See [Known limitations](#known-limitations).

## Quickstart

**Prerequisites:** Python 3.11, Docker + Docker Compose, a JDK (11/17/21) for PyFlink, and the PaySim CSV from [Kaggle](https://www.kaggle.com/datasets/ealaxi/paysim1) placed at `data/raw/PS_20174660362_1_log.csv`.

```bash
# 1. Install (the Makefile handles PyFlink's setuptools<81 / --no-build-isolation quirk)
python3.11 -m venv .venv && source .venv/bin/activate
make install-dev

# 2. Prepare data and train (logs to MLflow, registers the best model)
make preprocess
make train

# 3. Start the real-time feature platform
make infra-up && make flink-jar
make feast-apply && make materialize
make flink-worker                      # terminal 1: Kafka -> features -> Redis

# 4. Promote the model to "Production", then serve it
python - <<'PY'
from mlflow.tracking import MlflowClient
MlflowClient().transition_model_version_stage(
    name="fraud-detection-classifier", version=1, stage="Production")
PY
make api                               # terminal 2: http://localhost:8000/docs

# 5. Score a transaction
curl -X POST localhost:8000/predict -H "Content-Type: application/json" -d '{
  "step": 1, "type": "TRANSFER", "amount": 181.0, "nameOrig": "C1231006815",
  "oldbalanceOrg": 181.0, "newbalanceOrig": 0.0, "nameDest": "C1666544295",
  "oldbalanceDest": 0.0, "newbalanceDest": 0.0
}'
```

Run `make help` for every task. Detailed walkthroughs are in the [guides](#documentation).

## Features

| Area | What's implemented |
|---|---|
| **Data** | Ingestion, schema validation, quality report with plots, one-hot preprocessing, chronological train/val/test split |
| **Features** | Nine stateless engineered features in one shared `FeaturePipeline`, a feature registry with a version hash, deterministic Feast entity keys |
| **Training** | LR / Random Forest / XGBoost / LightGBM, class weighting for the 0.13% fraud rate, PR-AUC-based selection, MLflow tracking and Model Registry |
| **Streaming** | Kafka (KRaft) producer/consumer, real PyFlink job writing to Feast/Redis, per-record fault isolation |
| **Serving** | FastAPI `/predict`, `/health`, `/ready`, `/metrics`; model loaded once from the *Production* stage; 503 when features are missing |
| **Observability** | Prometheus metrics, auto-provisioned Grafana dashboard, `redis-exporter`, `cAdvisor`, Evidently data-drift reports from a real prediction log |
| **Operations** | Three Dockerfiles, Docker Compose stack, Kubernetes manifests (HPA 2–10 replicas, Ingress, PVCs, Secrets), three Airflow DAGs |
| **Quality** | 135 tests, ruff + black + mypy, pre-commit, GitHub Actions CI (lint/test, image builds, `kubeconform`, DAG import checks) |
| **Demo** | Streamlit dashboard that streams real rows through the live pipeline and shows live precision/recall against the ground-truth label |

## Known limitations

Documented openly rather than hidden — each one is a candidate next step:

- **Synthetic data, near-perfect scores.** PaySim's fraud is mechanically easy to spot; results will not transfer to real bank data.
- **Stateless features.** Every feature is computed from a single transaction. There are no account-history, velocity or rolling-window features, which is where most real fraud signal lives.
- **Flink runs in local-execution mode** at parallelism 1, with no event time, windows, keyed state or checkpointing ([ADR-0006](docs/decisions/0006-feast-redis-flink.md)).
- **No ground-truth feedback loop in production monitoring.** Live precision/recall is only computed in the Streamlit demo; Prometheus/Grafana track input and prediction distributions ([ADR-0008](docs/decisions/0008-monitoring.md)).
- **CI only, no automated CD.** Images are built but not pushed, and deployment to the local `kind` cluster is a manual `kubectl apply`.
- **Stress testing is not done** — HPA scale-up under load has not been demonstrated ([ADR-0009](docs/decisions/0009-deployment-and-operations.md)).
- **Airflow and Kubernetes training use a 38,213-row sample** (all fraud + 30,000 legitimate rows), because the full file exhausts the local Docker VM.
- **Local-only deployment**: single-node Kafka/Redis, no auth on the API, default dev passwords in compose files.
